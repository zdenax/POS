# Ovladače Zařízení (Device Drivers)

## Instrukce Zařízení

### Dva Základní Typy Zařízení

#### 1. **Znakové (Character) Zařízení**
- Pracují se znaky/bajty (po jednom)
- Příklady: klávesnice, terminál
- **Charakteristika:** Sekvenční přístup
- Data se čtou/zapisují postupně po sobě

#### 2. **Blokové (Block) Zařízení**
- Pracují s bloky dat
- Příklady: pevný disk
- **Charakteristika:** Náhodný přístup (random access)
- Lze se dostat na libovolné místo bez čtení předchozího obsahu
- Čtení a zápis je komplexnější než u znakových zařízení

## Služby (Operace) Ovladače

### Univerzální Operace
Operace dostupné pro všechna zařízení:
- **INIT** – Inicializace ovladače
- **TERMINATE** – Ukončení ovladače
- **OPEN** – Otevření zařízení
- **CLOSE** – Zavření zařízení
- **READ** – Čtení dat
- **WRITE** – Zápis dat
- **STRATEGY** – Strategie přístupu (optimalizace)

### Speciální Operace
Operace specifické pro určité typy zařízení (různé dle typu zařízení).

## Identifikace Ovladačů v Linuxu

V Linuxu se ovladače identifikují pomocí tří klíčových informací:

### 1. **Major Number (Hlavní Číslo)**
- Identifikuje typ ovladače (typ zařízení)
- Určuje, který ovladač bude použit
- Příklad: major 5 = terminál zařízení

### 2. **Minor Number (Vedlejší Číslo)**
- Identifikuje konkrétní zařízení daného typu
- Příklad: minor 0, 1, 2 = jednotlivé instance zařízení
- Lze zjistit příkazem `ls -l`

### 3. **Operace (Služba) + Parametry**
- Určuje, jakou operaci chceme provést
- Formát: `(major, minor, operace)`

#### Příklad:
```
major=5, minor=0, write  → zápis na zařízení major 5, instance 0
major=5, minor=1, read   → čtení ze zařízení major 5, instance 1
```

#### Tabulka Operací:
```
Operace:    0 (init)    1 (open)    2 (write)
────────────────────────────────────────────
Major 5:    init()      open()      write()
```

## Multitasking a Přerušení v Moderních Systémech

**Princip:** Moderní OS hlídají dobu, kterou ovladače běží, aby se předešlo dlouhým přerušením.

- Procesy se musí střidat a vzdávat se procesoru
- Každý proces by měl běžet jen krátkou dobu
- Umožňuje ostatním procesům dostat se na řadu
- Zajišťuje responsivnost systému

## Terminál – Příklad Komplexního Zařízení

Terminál obsahuje složité chování se vstupem a výstupem:

```
┌──────────────────────────────────────────┐
│        TERMINÁL ZAŘÍZENÍ (TTY)           │
├──────────────────────────────────────────┤
│                                          │
│  VSTUP (INPUT BUFFER):                   │
│  Klávesnice → RAW buffer                 │
│  └─ Ukládají se surové znaky             │
│                                          │
│  ZPRACOVÁNÍ:                             │
│  ├─ Korekce (backspace,Delete)          │
│  ├─ Vlastnosti řádku (line editing)      │
│  └─ Echo (zobrazení znaků)               │
│                                          │
│  VÝSTUP (OUTPUT BUFFER):                 │
│  └─ Zobrazení na obrazovku               │
│                                          │
└──────────────────────────────────────────┘
```

## Souborový Systém

### Obecně
- Různé formáty: NTFS (Windows), EXT4 (Linux), APFS (Mac)
- Zaměřujeme se na UNIX/Linux souborový systém

### Struktura Souborového Systému

```
┌─────────────────────────────────────┐
│  Otevřený soubor (File Descriptor)  │
├─────────────────────────────────────┤
│  Mount (připojení souborových)      │
├─────────────────────────────────────┤
│  Adresářová struktura (Inodes)      │
├─────────────────────────────────────┤
│  Vyrovnávací paměti (Buffers)       │
│  - Nejde jen o rychlost             │
│  - Nutné pro správné fungování      │
├─────────────────────────────────────┤
│  Logické svazky (Volumes)           │
│  Driver (řídící software)           │
├─────────────────────────────────────┤
│  Partice (Image na disku)           │
├─────────────────────────────────────┤
│  Hardware (Vnější paměť)            │
└─────────────────────────────────────┘
```

### Struktura Disku

```
┌────────────────────┐
│   BOOT SEKTOR      │  ← Spouštěcí sektor
├────────────────────┤
│  HEADER SEKTOR     │  ← Metainformace
├────────────────────┤
│   METADATA         │  ← Informace o souboru
├────────────────────┤
│     DATA           │  ← Samotná data souborů
├────────────────────┤
│ METADATA (přídavné)│  ← Další informace
└────────────────────┘
```

## Otázka: Proč je tento přístup dnes již zastaralý?

- Původní návrh datových struktur nepředpokládal dnešní kapacity
- Neefektivní pro velmi velké disků a soubory
- Fragmentace paměti
- Problémy s výkonem u moderních aplikací
- Potřeba nových technologií (SSD, Cloud Storage)
