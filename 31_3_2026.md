# Synchronizace a Komunikace Procesů (31.3.2026)

## Část 1: Synchronizace bez Zámků

### Reference Counting

**Problém - Race Condition:**

Při inkrementaci proměnné bez zámku:

```assembly
m.lock()
mov rax, [i]    ; Čti hodnotu i
inc rax         ; Inkrementuj
mov [i], rax    ; Zapiš zpět
m.unlock()
```

**Python reference counting:**

```python
m = []
n = [n]
m.append(n)
```

Pokud objekty zaniknou bez správného reference counting, neuvolní se z paměti. Proto máme garbage collector, který uvolňuje tyto chyby když ref. counting nefunguje. Řešením jsou zámky, odemykání a atomické operace.

### Mutex-like Spinlock

```c
// Jednoduchý spinlock s CAS
desired_value = getpid()
expected_value = 0
loop:
    old_value = CMPXCHG(&mutex, expected=expected_value, desired=desired_value)
    if old_value == expected_value:
        return
```

### Reentrant Lock (Vícenásobné zámkování)

```c
// Složitější - vlastník PID si může zámek vzít znovu
lock():
    if addr == getpid():
        counter++    // Jsem vlastník, mohu zvýšit počitadlo
        return

    // Jinak čekám na CAS
    desired_value = getpid()
    expected_value = 0
    loop:
        old_value = CMPXCHG(&mutex, expected=expected_value, desired=desired_value)
        if old_value == expected_value:
            counter = 1
            return

unlock():
    if addr == getpid():
        counter--
        if counter == 0:
            addr = 0
```

**Poznámka:** ARM procesory (M1, M2, M3) a mikrokontrolery jako Raspberry Pi Pico 2 s Cortex-M33 mají speciální instrukce pro CAS operace.

## Část 2: Komunikace mezi Procesy (IPC)

### Dvě základní dimenze komunikace

**1) Přímostnost komunikace:**
- **Přímá:** Sdílená paměť
  - RDMA (Remote Direct Memory Access) - efektivní síťová komunikace
- **Nepřímá:** Komunikace přes kernel (kopírování přes jádro)

**2) Orientace:**
- **Zprávově orientovaná:** Out-of-order, broadcasting
- **Proudově orientovaná:** Efektivnější, jediný mechanismus je proud bytů

---

### Roury (Pipes)

**Charakteristika:**
- Proudově orientované
- Klasické unixové
- Jednosměrné
- Anonymní: `ls | wc -l`

**Implementace v shellu:**

```c
int p[2];
p = pipe();  // p[0] - čtení, p[1] - zápis

if (!fork()) {
    // Proces LS
    close(p[0]);      // Nepotřebuji číst
    close(1);         // Uzavřu stdout
    dup(p[1]);        // Přesměruju stdout na p[1]
    close(p[1]);
    execp("/bin/ls");
}

if (!fork()) {
    // Proces WC
    close(p[1]);      // Nepotřebuji psát
    close(0);         // Uzavřu stdin
    dup(p[0]);        // Přesměruju stdin na p[0]
    close(p[0]);
    execp("/bin/wc");
}

for (int i = 0; i < 2; i++)
    wait();
```

**Podmínka:** Oba procesy musí mít stejného rodiče, který rouru vytvoří.

**Cyklická fronta v jádru:** Velikost 4KiB, synchronizovaná.

### Pojmenované Roury (FIFO)

- Jednosměrné
- Viditelné v souborovém systému
- Umožňují komunikaci mezi cizími procesy
- Windows: obousměrné, nejen lokální ale i síťové

---

### Sockety

**TCP Sockety (síťové):**
- Proudově orientované (existují i zprávy orientované varianty)
- Obousměrné
- Synchronizované
- Používají síťový protokol (TCP/UDP/IP)

**Unix Sockety (lokální):**
- Obousměrné
- Pojmenované
- Otevírají se jako soubory (sdílený identifikátor v souborovém systému)

**Navázání spojení (Three-way Handshake):**

```c
socket =  Socket(my_ip, TCP);      // Half-socket
socket = connect(socket, server_ip, server_port);  // Nový socket po spojení

// Na původním socketu lze navázat další spojení
```

**Výsledný socket obsahuje:**
```
[server_ip, server_port, client_ip, client_port, protocol]
```

Nejdůležitější je **client_port** - jedinečně identifikuje klientskou stranu spojení.
